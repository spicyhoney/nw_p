## 三、主辦方提供的資料與使用邊界

### 提供內容

- 服務商與服務項目主檔，含清潔、寄件、餐廳訂位、外送、水電修繕、購物等類型。〔《企業數據工作坊簡報》p.8〕

- 訂單紀錄 DDL 與 CSV／JSON 範例，包含狀態、金額、點數、服務商資料與訂單明細。〔《企業數據工作坊簡報》p.10、p.17–18〕

### 會影響實作的資料規則

- 若採用官方 schema／樣本，需保留可追溯的 PK／FK、來源及匯入順序；不得把斷裂關聯自行補成真實資料。官方文件提供建議載入順序。〔《企業數據工作坊簡報》p.11〕
- 諮詢與訂單 schema 把姓名、電話、Email、詳細地址列為加密欄位，文件建議 AES-256-GCM；查詢欄位建議 SHA-256 hash。這是正式個資設計的重要基線，但現有產品尚未宣稱已完成。〔《企業數據工作坊簡報》p.16、p.18〕
- 訂單以 `order_no + service_id` 唯一鍵避免重複匯入；若未來對接該表，冪等設計不得破壞此意圖。〔《企業數據工作坊簡報》p.18〕
- CSV 可供測試／bulk import／Athena，JSON 可供 API／DynamoDB；這些是匯入選項，不是指定 AWS 技術。〔《企業數據工作坊簡報》p.10〕
- PDF 未明列資料授權、公開 GitHub 範圍、外部模型傳輸權或保存期限。因此延續團隊較嚴格政策：原始資料不公開、不送外部模型；synthetic／curated／official-derived 必須清楚標籤。授權範圍仍待主辦方確認。

### 提供來源沒有明確要求

兩份 PDF 與目前補充公告都沒有明文指定：

- Demo 必須部署在 AWS。
- 必須使用 Amazon Bedrock、AgentCore、RDS、S3、Lambda、DynamoDB、Athena 或特定 foundation model。
- 固定 AWS Region、帳號、IAM 架構、網路拓樸或資料落地區域。
- MCP 必須由 AgentCore Gateway 託管，或必須公開為某種 transport。

工作坊資料提到可把 JSON 匯入 DynamoDB、CSV 用於 Athena，屬格式用途示例，不是指定架構。〔《企業數據工作坊簡報》p.9–10〕

因此 Bedrock、AgentCore、RDS、S3、IAM、CloudWatch 與 AWS hosting 目前均屬團隊候選方向。簡報可提出目標架構，但必須清楚區分「已完成本機 baseline」、「最終 Demo 實際部署」與「未來 AWS 目標」。
