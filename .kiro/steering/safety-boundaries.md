# 安全與資料邊界

以下規則適用所有 Spec、程式、Demo、測試與文件。若需求與此處衝突，先停止並要求人工決策。

## 1. 地點與地址不得猜測

- 不得預設臺北市、目前位置、戶籍地、GPS 位置或任何服務地址。
- 縣市與行政區缺少、互相矛盾、結果不存在或不唯一時，必須追問；不得選第一筆或用模型常識補值。
- 「人在高雄、服務地點在臺北」等敘述必須確認哪一處才是服務地址。
- 精確門牌屬高敏感住家資訊；目前 synthetic Demo 不得收真實門牌。未來只有在目的、接收方、保存期間與刪除方式明確且使用者同意後，才可最少量收集。

## 2. 個資、同意與揭露

- 目前僅允許 synthetic contact；不得暗示已具備正式個資處理能力。
- 真實姓名、電話、Email、精確地址、聲音與可識別住家照片上線前，必須完成 consent、加密／金鑰管理、查詢 hash、RBAC、多租戶隔離、保存期限、刪除與 incident policy。
- 不得要求與服務無關的身分證字號、金融資料、健康資料或其他過度資訊。
- 同意必須具體、可理解、不可預先勾選，並區分保存、外部模型處理、分享給服務商與行銷用途。
- pending provider 只能看到完成工作所需的遮罩資料；只有被指派且接受案件的授權對象才可取得必要聯絡資訊。拒絕、未指派或未登入者不得取得。
- log、audit、error、analytics、prompt、Tool trace、截圖與 Demo 影片不得含完整個資或秘密。

## 3. 真人轉接

- 「可隨時要求轉真人」是產品方向，現況尚未實作；系統不得假裝已通知真人或承諾回覆時間。
- 未來任何對話階段都應能提出轉接；提出後不得以成癮式或阻擋式流程強迫繼續與 AI 對話。
- 轉交摘要、聯絡方式、照片或歷史對話前，要告知接收者與資料範圍並取得同意。
- 模型不確定、連續失敗、偵測到安全風險或使用者明確要求時，應提供安全退出／真人路徑；實際 channel、營業時間、SLA、責任歸屬仍待人工決定。
- 緊急漏水、漏電、瓦斯、火災或人身危險不得包裝成一般媒合保證；需顯示適當的立即安全指引與官方緊急聯絡方式，內容須由人審核。

## 4. 模型與對話失敗

- 模型不得生成或猜測 service ID、location ID、form field、provider、時段、案件、訂單、地址或工具結果。
- 無資料、低信心、歧義、provider timeout、schema 不符或 Tool error 時，應明說無法確認，要求澄清、重試或轉真人。
- 不得靜默從真模型切換到 Mock，也不得把 Mock／synthetic 結果呈現為正式結果。
- 模型文字不能直接修改業務狀態；派單、接單、拒絕、刪除、分享資料與未來付款均需受控 UI／API、明確確認及 Service Layer 驗證。
- 限制 model steps、每輪 Tool calls、request timeout 與輸出 schema，避免無限迴圈、成本失控與 prompt injection 擴權。

## 5. 語音安全

- STT／TTS 尚未實作。引入前須決定 provider、資料流、語言／腔調支援、錄音保存與刪除政策。
- 開始錄音與送往外部語音服務前必須有清楚提示與同意；預設不永久保存原始音訊。
- 台語／國語轉寫必須以繁體中文回顯給使用者確認後，才可作為地址、時間、預算、緊急程度、聯絡資料或寫入動作的依據。
- 不得從口音推測族群、身分、能力或服務資格；TTS 不得冒充特定真人。

## 6. 照片與住家隱私

- 正式政策完成前，只能使用 synthetic／公開測試圖片；不得上傳臉孔、證件、門牌、信件、螢幕、家庭成員或其他可識別資訊。
- 每次傳送外部 VLM 前取得明確同意，說明 provider 與資料會離開本機邊界；同意不可沿用成無限期授權。
- 只能接受實際 decode 成功且在允許格式／大小內的圖片；伺服器重新命名、重編碼、移除 metadata，拒絕偽 MIME、path traversal、symlink 與損壞檔。
- 圖片保持 private、`no-store`、授權 endpoint；不得在 API、log、audit 或 Browser model 暴露內部 path。
- VLM 只提供建議；使用者可修正且必須確認，再以既有服務目錄重驗。不得依照片直接派單、判定危險等級或取代專業檢查。
- retention、刪除、備份、跨區傳輸、S3 lifecycle 與事件處理尚待決策。

## 7. 外部工具與服務呼叫

- Agent 僅能看到明確白名單、最小參數、schema 驗證且有 timeout 的 Tools。
- 目前四個 MCP Tools 全部唯讀；不得透過改 annotation、prompt 或隱藏 endpoint 繞過限制。
- Agent 不得執行 SQL、shell、任意 HTTP、任意檔案操作或由使用者提供的程式碼。
- 所有 SQL 固定且參數化，並由 repository 執行；read path 僅查安全 views。
- 未來寫入 Tool 需要 authentication、authorization、明確確認、idempotency、transaction、audit、replay protection 與最小 scope。
- 將對話、音訊、照片、Tool schema 或資料送往任何第三方前，需做資料最小化、揭露、同意、供應商與 Region 審查；不得把主辦方原始資料、秘密或真實個資送給未核准服務。

## 8. Token、資料庫與 AWS

- 不得讀取、顯示、提交或寫入 `.env`；任何 token、密碼、資料庫 URL、AWS key、cookie 或個資不得進 steering、Spec、程式碼、測試 fixture、文件、commit、prompt 或輸出。
- credential 只能由環境或標準 provider chain 取得；部署使用 IAM role／短期 credential，不使用長期 hard-coded key。
- AWS 採最小權限、資源隔離、加密、成本上限與可稽核 log；Region、服務、模型與權限未確認前不得假設。
- 測試只連明確標示的隔離測試資料庫；不得連正式資料庫或以未知 URL 嘗試 migration／清除資料。
- 公開 GitHub 的完整原始碼要求不包含秘密、原始受限資料、真實個資或私有媒體。

## 9. 點數與高齡倫理

- 不得單純依聊天次數、訊息數、停留時間、連續登入或提供更多個資發點。
- 點數 Spec 必須先評估洗點、詐欺、成癮、誤導、差別待遇、隱私、撤銷／退款、未成年人與高齡者理解風險。
- 服務品質、安全或真人協助不得因未參加點數而被降低。
- 模型不得自行承諾、計算、扣除或補發點數；必須由可稽核規則與 ledger 決定。

## 10. Spec 安全檢核

每份 Feature Spec 至少回答：資料來源與接收者、需何種同意、失敗／歧義處理、人工出口、副作用確認、身分與權限、保存與刪除、audit、synthetic／真實資料界線、測試是否隔離，以及哪些 claim 可由證據支持。
