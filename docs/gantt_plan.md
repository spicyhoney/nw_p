# gantt_plan.md — 時程與甘特規劃（2026/7/8 → 8/2）

> 前提：兩人（A=資工、B=統計），每天可投入 2–3 小時（週末可 4–6）；7/18 上午工作坊（公布 EDIMUS/Ademus 規格）；7/22 疑似入選/重要節點；8/1–8/2 決賽現場 30 小時。
> 排程原則：**每週實際產能抓 15–18 人時**（不是理想的 40）；每階段留 25% buffer；所有「AWS 增量」都可整段砍掉而不影響 demo 成立。

## 2. 7/18 工作坊前準備（帶著答案去換答案）

**先做完**（否則問不出好問題）：T01/T02/T04 通過、MCP 概念清楚、容器化方案就緒。

**必問清單**：
1. EDIMUS/Ademus 是什麼形態——給 VM？容器平台？PaaS？能跑 Docker Compose 嗎？
2. 有沒有提供 AWS 帳號/額度？Bedrock 在哪個 region、哪些模型開放？
3. MCP Server 的驗收方式：Lumine one 用什麼 transport 接（stdio/HTTP）？有沒有調用範例？
4. Kiro 加分的具體認定：查 GitHub 什麼痕跡？`.kiro/` 目錄？commit 訊息？使用時數 log？
5. 官方說會提供的 YAML/README 補充資料何時給？
6. 決賽現場：網路品質、能否用自己的雲資源、8/1 現場公告的交付格式先透露多少？
7. `order_type=07`／`service_id=18` 的定義（順便展示你們讀了資料，留下印象）。

## 6. 最小成功標準（低於此不算可上台）

1. 消費者輸入一句生活需求 → AI 正確分類＋至少 2 輪追問 → 產生諮詢單入庫（PII 加密）
2. 媒合推薦 ≥2 家廠商並附理由
3. 廠商後台看到案件＋AI 摘要 → 按接案 → 消費者端看到狀態更新
4. MCP Server 至少 3 個 tool 可被 Inspector（或 Lumine one）調用——有錄影證據
5. 簡報含 AWS 架構圖＋官方資料應用說明；GitHub 可 clone 跑起；demo 影片已錄
> 語音、照片、Lambda、統計儀表板、第二場景——全部是加分，不在最小標準內。

## 7. 禁止事項（時間有限時的紅線）

1. **不碰金流**（官方明說；「訂單成立，請於 X 日前完成付款」一句話帶過）
2. **不用真實廠商名稱**（官方明說；全用虛構商號，demo 前全文搜一次真品牌字樣）
3. demo 場景不超過 2 個服務類型（第 3 個用「已支援」示意卡）
4. 不從零學 Bedrock Agents Classic、Step Functions、k8s、VPC 等重 infra
5. 不做無法 demo 的功能（沒有 UI 入口的後端功能＝不存在）
6. 不依賴不穩定外部 API（地圖、真餐廳資料、LINE 通知——全用假資料/站內通知）
7. 不在 7/27 之後加新功能、不在決賽 18h 後寫新 code
8. 不讓 LLM 直寫 DB（一律過 tool 白名單）；不在 demo 用真人個資
9. 不熬夜寫 code 到上台前——完成度分數死在恍神的 live demo 上最冤
